# 文件整理：多个文件夹 × 多种整理强度 — 设计

日期：2026-10-31 · 状态：待审阅（范围为小改动，写成简短设计）

## 意图

现在“文件整理”只有一个当前文件夹和一对阈值（久未动的天数、最近写入的等待分钟），都只能存一份。用户希望：**保存多个文件夹，也保存多种整理强度，两者是多对多**——同一种强度可以用在几个文件夹上，同一个文件夹也可以随时换另一种强度；每个文件夹记住自己上次用的强度。

## 目标 / 非目标 / 反目标

- 目标：文件夹列表、强度列表、每个文件夹上次用的强度，重启后还在；切换后下一次扫描立刻按新的来。
- 非目标：自定义分类规则、按文件夹设置不同的分类（这仍是以后的事）；强度重命名；导入导出。
- 反目标：任何一种切换都不能让引擎对“当前文件夹之外”的路径动手（PathGuard 不变）；删除强度或文件夹不能删用户的文件。

## 我的决定（审阅时请看这几条）

1. **模型**：两张互相独立的列表 + 一张“文件夹 → 强度名”的配对表。多对多不需要额外的连接表。
2. **强度 = 名称 + 两个阈值**（1–3650 天、0–1440 分钟，范围与 `TidyOptions` 一致）。名称不能为空、最长 20 个字、不区分大小写不可重复。至少保留一个；首次使用时只有一个叫“标准”的强度（默认 90 天 / 5 分钟）。
3. **文件夹**：下载文件夹始终在列表里且不能移除；其余由用户添加，添加时走现有的 `FolderChoice.Validate`。路径统一成去掉末尾分隔符的完整路径，不区分大小写去重。“移除”只是从列表里去掉，不碰磁盘上的任何文件。
4. **删除一个强度**：用了它的文件夹改用剩下的第一个强度。
5. **历史和“已保留”不变**：整理历史已经按当前文件夹过滤（`DownloadsModule.GetHistory`），所以天然是每个文件夹各一份，不需要改。
6. **保存位置**：`%LOCALAPPDATA%\TidyBox\Downloads\profiles.json`，和 `kept.json` 同处，不上传。文件损坏就当作第一次使用。
7. **迁移**：旧的 `Tidy.Folder`、`Tidy.StaleDays`、`Tidy.RecentMinutes`（LocalSettings）读一次，作为起始的文件夹和“标准”强度，然后删掉这三个键。
8. **界面**：文件整理页顶部放两个下拉框“文件夹”“整理强度”，现有的“更改文件夹…”改成“添加文件夹…”，再加“从列表移除”；设置页里“文件整理”卡片改成管理强度（下拉选择要编辑哪一个 + 两个数字框 + 新建/删除/恢复默认值）。

## 方案比较

| 方案 | 说明 | 取舍 |
|---|---|---|
| A 独立两张列表 + 配对表（选） | 文件夹、强度各自管理，当前选择各选一项 | 正好是多对多；每个文件夹自动记住强度；多一个“配对”概念 |
| B 命名方案（名称+文件夹+阈值） | 一个方案绑死一个文件夹 | 简单，但同一强度改一次要改 N 处，不是多对多 |
| C 只给每个文件夹存阈值 | 阈值挂在文件夹上 | 最省事，但没有可复用的“强度”，与需求不符 |
