# 用户反馈功能（Cloudflare Workers + D1）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 PowerTools 设置页加一个"发送反馈"入口：文字 + 可选联系方式 + 版本号，选"错误"时可附带（脱敏后的）运行日志；请求发到作者的 Cloudflare Worker，存进 D1。

**Architecture:** 三块各自可独立测试。`server/feedback-worker/`（TypeScript Worker：校验 + 限额 + 写 D1，用真实 D1 跑测试）；`PowerTools.Core` 里的 `Feedback`（HTTP 客户端、限额常量、日志截断）和 `Logging`（`AppLog` 文件日志、`LogRedactor` 脱敏），xUnit 覆盖；App 层只做设置页入口、对话框和日志埋点（Windows 行为手动验证）。

**Tech Stack:** Cloudflare Workers + D1、wrangler、TypeScript、vitest ^4.1 + `@cloudflare/vitest-plugin`；.NET 8、WinUI 3、xUnit 2.5.3、`System.Text.Json`、`HttpClient`。

**Spec:** `docs/superpowers/specs/2026-10-28-feedback-design.md`（执行者须先读，尤其第 3 节"我的决定"与第 6 节接口契约）。

## Global Constraints

- 分支：从 `master` 新建 `feat/feedback`；不在 `master` 上直接开发。
- 工作区里 `CLAUDE.md` 有用户有意保留的本地改动，**绝不暂存它**；每次提交只 `git add` 本计划列出的路径。提交信息前缀 `feat:`/`fix:`/`docs:`/`chore:`。
- Windows 11 only；PowerTools 为 MSIX 全信任，普通权限运行。
- `kind` 取值：`suggestion` / `error` / `other`（Worker 与客户端一致，小写）。
- 限制：`message` trim 后 1–4000（UTF-16 长度）；`contact` 可选，trim，空串视为无，≤200；`appVersion` 匹配 `^\d{1,5}\.\d{1,5}\.\d{1,5}\.\d{1,5}$`；`logs` 仅 `kind == "error"`，UTF-8 ≤ 65536 字节；整个请求体 ≤ 131072 字节（128 KB）。
- 接口：`POST /v1/feedback`；状态码 201 `{"id":n}`、400 `{"error":"invalid_request","field":"…"}`、404 `{"error":"not_found"}`、405 `{"error":"method_not_allowed"}`、413 `{"error":"too_large"}`、429 `{"error":"rate_limited"}`、503 `{"error":"busy"}`、写库失败 500。
- 限额：单个 IP 哈希每小时最多 5 条；全站每天最多 2000 条。检查顺序：方法/路径 → 请求体大小 → JSON → 字段校验 → 单 IP 限额（429）→ 全站限额（503）→ 写库。
- IP 只存哈希：SHA-256(`IP_HASH_SALT` + IP) 的 64 位十六进制；取自 `CF-Connecting-IP`，缺失时按 `"unknown"`。不存原始 IP、系统版本、设备 ID。
- 表 `feedback` 字段：`id`、`created_at`（UTC ISO 8601）、`kind`（CHECK）、`message`、`contact`、`app_version`、`logs`、`ip_hash`；索引 `created_at` 与 `(ip_hash, created_at)`。
- 测试用 `@cloudflare/vitest-plugin`（`@cloudflare/vitest-pool-workers` 已废弃并改名为它；1.4.9，peer 为 `vitest ^4.1 || ^5`），`vitest` 取 `^4.1`。TypeScript 用 5.x。
- 日志：`%LOCALAPPDATA%\PowerTools\logs\powertools.log`，超过 512 KB 滚动为 `powertools.1.log`（只留一份旧的）；永不抛异常；每行同步写入。脱敏：用户目录路径 → `%USERPROFILE%`，用户名 → `<user>`，机器名 → `<machine>`；短于 3 个字符的名字不替换。发送的日志最多最近 64 KB，在行边界截断。
- 客户端固定文案：已发送 `已发送，谢谢你的反馈。`；被拒绝 `内容不符合要求，请检查后再发送。`；太频繁 `发送太频繁，请稍后再试。`；无法连接 `无法连接到反馈服务器，请检查网络后重试。内容已保留。`。`HttpClient` 超时 10 秒。
- `FeedbackConfig.Endpoint` 为空时，设置页**不显示**反馈区。
- 普通 `dotnet build` 不会刷新已注册 dev 包的布局（`src\PowerTools.App\bin\x86\Debug\net8.0-windows10.0.26100.0\AppX`）；运行 App 的验证要先把新的 dll/exe/`resources.pri` 同步进去。
- Worker 命令都在 `server/feedback-worker/` 里执行。

## Review Focus

按最可能影响使用者的顺序，每条后面是持有其测试/验证的任务：

1. 内容为空白、全是 emoji、恰好 4000 / 4001 个字符、请求体超过 128 KB、JSON 损坏或不是对象——应得到 400/413，**不写库**（Task 1、Task 2）。
2. `logs` 出现在非 `error` 类型上，或超过 64 KB（含多字节字符）——被拒绝；客户端在非错误类型时从不发送 `logs`（Task 1、Task 3）。
3. 同一 IP 连续提交、不同 IP 互不影响、一小时后恢复、全站日限额——429/503 行为正确（Task 2）。
4. 服务器连不上、DNS 被拦、超时（大陆场景）——对话框保持打开、内容保留、提示明确、不崩溃、不超过超时时间才返回（Task 3 假处理器测试 + Task 6 手动）。
5. 日志里含用户名、用户目录路径、机器名——预览和发送出去的都已脱敏；日志写入失败不影响应用（Task 4）。
